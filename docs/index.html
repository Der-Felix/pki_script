OpenSSL Homelab PKI Suite

A modular, production-ready, file-based X.509 Public Key Infrastructure (PKI) suite engineered for homelabs, staging clusters, and enterprise systems using OpenSSL 3.x.

OpenSSL 3.0+ Bash 4.x / 5.x RFC 5280 Compliant Zero Dependencies MIT Licensed
Key Highlights

Divided into 17 clean, specialized modules under lib/. Features an interactive terminal wizard, 1-click DNS autodetection for TLS servers, full tab completion, automated copy-paste deployment guides (GUIDE.txt), and 12 production-tuned certificate presets.

PKI Architecture

This suite creates an industry-standard, two-tier hierarchical PKI designed for maximum operational security:

Two-Tier CA Trust Hierarchy
                  ┌──────────────────────────────────────────┐
                  │                 Root CA                  │  RSA 4096 / 20 Years
                  │  (Self-signed, offline/storage safe)     │  Signs ONLY Intermediates & CRLs
                  └────────────────────┬─────────────────────┘
                                       │
                      ┌────────────────┴────────────────┐
                      ▼                                 ▼
         ┌─────────────────────────┐       ┌─────────────────────────┐
         │     Server-CA (Issuing) │       │     Client-CA (Issuing) │  RSA 4096 / 10 Years
         │   (pathlen:0, serverAuth│       │   (pathlen:0, clientAuth│  Restricted by role
         └────────────┬────────────┘       └────────────┬────────────┘
                      │                                 │
           ┌──────────┴──────────┐           ┌──────────┴──────────┐
           ▼                     ▼           ▼                     ▼
      Web Servers         Proxmox / NAS    mTLS Clients      802.1X EAP-TLS
      (Nginx/Caddy)       (PVE / TrueNAS)  (APIs / curl)     (WiFi / Switches)
  • Root CA: Uses RSA 4096 with strict basicConstraints=critical,CA:TRUE. It never issues leaf certificates directly.
  • Intermediate CAs: Dedicated issuing authorities restricted by pathlen:0 (cannot create sub-CAs), optional Name Constraints, and Extended Key Usages.
  • Leaf Certificates: Issued using modern standards (RSA 3072 or Ed25519), strict SAN validation, and automated chain bundling (fullchain.pem, combined.pem, cert.p12).

30-Second Quickstart

Get a full Root CA, two Intermediate CAs, and your first verified certificate running in under a minute:

1. Clone Repository & Verify Health

Terminal
git clone https://github.com/Der-Felix/pki_script.git
cd pki_script
chmod +x pki.sh build.sh pki completions/pki.bash
./pki.sh doctor

2. Initialize CA Hierarchy

Initializes the Root CA and two issuing authorities for servers and clients:

Terminal
./pki.sh init --org "Homelab" --intermediate server-ca --intermediate client-ca

3. Issue a Server Certificate in 1 Click

The quick command queries DNS to automatically discover your FQDN, short aliases, and all host IP addresses:

Terminal
./pki.sh quick web01.homelab.lan

4. Verify Certificate Chain & Key Match

Terminal
./pki.sh verify web01.homelab.lan --host web01.homelab.lan

Certificate Profiles (Presets)

Filter or search through all 12 pre-configured certificate presets:

server TLS Server
Web servers, reverse proxies, LDAPS, Proxmox, UniFi, mail servers, databases.
EKU: serverAuth
Key: RSA 3072 (or Ed25519 for internal)
Validity: 397 days (Apple/CAB compliant)
Required SANs: DNS or IP
./pki.sh issue server --cn web.lan --dns web.lan,www.lan --ip 10.0.0.5
wildcard TLS Server
Covers *.domain.lan plus base domain for central ingress proxies (Traefik/Nginx).
EKU: serverAuth
Key: RSA 3072
Validity: 397 days
Required SANs: Wildcard domain
./pki.sh issue wildcard --domain homelab.lan
client Client Auth
802.1X EAP-TLS (WiFi/Switch port), mTLS microservices, browser authentication, REST APIs.
EKU: clientAuth
Key: RSA 3072 / Ed25519
Validity: 730 days (2 years)
Export: PKCS#12 (.p12)
./pki.sh issue client --cn user-laptop --p12

802.1X EAP-TLS Network Authentication (WiFi / LAN)

EAP-TLS is the golden standard for enterprise wireless (WPA2/WPA3-Enterprise) and dynamic 802.1X switch port security. Passwords are never transmitted over the air; authentication relies exclusively on cryptographic client certificates.

1. Issue Client Certificate

Using the pre-built template from examples/network-auth-8021x.conf:

Terminal
./pki.sh batch examples/network-auth-8021x.conf

2. Client Deployment

  • Windows / macOS / iOS / Android: Import the generated pki/issued/laptop-felix-8021x/cert.p12 into the user certificate store. Install pki/publish/root.crt into Trusted Root Authorities.
  • Linux wpa_supplicant.conf:
    /etc/wpa_supplicant/wpa_supplicant.conf
    network={
    ssid="Homelab-Enterprise"
    key_mgmt=WPA-EAP
    eap=TLS
    identity="laptop-felix"
    ca_cert="/etc/ssl/pki/root.pem"
    client_cert="/etc/ssl/pki/laptop-felix.pem"
    private_key="/etc/ssl/pki/laptop-felix.key"
}

Web Servers & Reverse Proxies

Every issued certificate directory includes a complete set of bundles and an auto-generated GUIDE.txt with tested configuration blocks:

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name web01.homelab.lan;

    ssl_certificate     /etc/ssl/web01/fullchain.pem;
    ssl_certificate_key /etc/ssl/web01/key.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
# dynamic.yml (Traefik File Provider)
tls:
  certificates:
    - certFile: /certs/fullchain.pem
      keyFile:  /certs/key.pem
  stores:
    default:
      defaultCertificate:
        certFile: /certs/fullchain.pem
        keyFile:  /certs/key.pem
web01.homelab.lan {
    tls /etc/ssl/web01/fullchain.pem /etc/ssl/web01/key.pem
    reverse_proxy 127.0.0.1:8080
}
<VirtualHost *:443>
    ServerName web01.homelab.lan
    SSLEngine on
    SSLCertificateFile    /etc/ssl/web01/fullchain.pem
    SSLCertificateKeyFile /etc/ssl/web01/key.pem
    SSLProtocol -all +TLSv1.2 +TLSv1.3
</VirtualHost>
# HAProxy requires combined.pem (private key + certificate chain in 1 file)
frontend https-in
    bind :443 ssl crt /etc/haproxy/certs/combined.pem alpn h2,http/1.1
    default_backend app_servers
# Copy directly to Proxmox proxy SSL directory
scp fullchain.pem root@pve-node1:/etc/pve/local/pveproxy-ssl.pem
scp key.pem       root@pve-node1:/etc/pve/local/pveproxy-ssl.key
ssh root@pve-node1 'systemctl restart pveproxy'

Trusting the Root CA on Clients (Once per device)

To ensure browsers, CLI tools, and operating systems trust your homelab certificates without warnings, install the public Root CA certificate from pki/publish/root.pem:

Platform Installation Command
Debian / Ubuntu / Proxmox sudo cp pki/publish/root.pem /usr/local/share/ca-certificates/homelab-root.crt && sudo update-ca-certificates
RHEL / Rocky / Fedora sudo cp pki/publish/root.pem /etc/pki/ca-trust/source/anchors/homelab-root.pem && sudo update-ca-trust
macOS sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain pki/publish/root.pem
Windows (PowerShell Admin) Import-Certificate -FilePath .\pki\publish\root.crt -CertStoreLocation Cert:\LocalMachine\Root
Firefox (Use OS Trust Store) In about:config, set security.enterprise_roots.enabled to true.

Verification & Key Matching

The verify command performs a strict 4-point verification check against the actual CA database and CRLs:

  1. Validates complete X.509 certificate trust chain up to the Root CA.
  2. Checks Certificate Revocation Lists (CRL) for both Intermediate and Root CAs.
  3. Verifies hostname or IP matching (SAN validation).
  4. Performs a cryptographic Public Key Match to verify the private key corresponds exactly to the certificate.
Terminal
./pki.sh verify web01.homelab.lan --host web01.homelab.lan

CLI Reference & Headless Automation

Every interactive operation in pki.sh can be fully automated in cron jobs, SaltStack states, or Ansible playbooks using CLI flags and environment variables:

Environment Variable Description Example
PKI_DIR Repository storage directory (defaults to ./pki) /etc/pki/homelab
PKI_CA_PASS Master passphrase for all CA keys secure-vault-passphrase
PKI_CA_PASS_<NAME> Specific CA passphrase override PKI_CA_PASS_SERVER_CA="pass"
PKI_KEY_PASS Passphrase for encrypted leaf keys key-passphrase
PKI_P12_PASS Password used when packaging .p12 archives export-password
NO_COLOR=1 Disables ANSI colors in terminal and log outputs 1

Automated Renewal Cronjob

Runs every night at 03:00, checks if any certificate expires in the next 30 days, and automatically renews it:

/etc/cron.d/pki-renewal
0 3 * * * root PKI_DIR=/opt/pki /opt/pki_script/pki.sh check --days 30 || /opt/pki_script/pki.sh renew web01 --revoke-old -y
